# 同城商品管理页面原型 v0.1

这是一个可直接打开的静态页面原型，不依赖前端工程和安装命令。

当前版本已按 PC 功能菜单和同城 App 内功能菜单拆分页面片段、CSS、JS，拆分说明见 `SPLIT_GUIDE.md`。

## 页面入口

打开：

`index.html`（本工程根目录）。

也可在本工程目录运行 `node server.mjs`，然后访问 `http://127.0.0.1:4173`。服务仅监听本机地址，无需安装第三方依赖；可通过 `PORT` 环境变量修改端口。

京东接口调试的真实请求需要上述 Node 服务及手动输入有效凭据；GitHub Pages 等纯静态预览不提供此代理接口。工程不预填真实 Token、AppKey 或 AppSecret，请勿将真实凭据提交到仓库。

## 已实现交互

- 同城 → 同城基础设置 → 同城商品库存对比：参照截图复刻 21 列库存比对明细及合计行，默认标超店、创建日期 2026-11-08。支持筛选展开/收起、查询、重置、门店区域选择、批量输入/导入商品编码、显示列设置、分页、CSV 导出及本次会话导出记录；合计与导出均基于当前查询结果。提供 30 条本地演示记录，不连接实际库存或执行库存补偿。

- 同城 → 同城基础设置 → 小程序商家客服：顶部按微信客服ID、员工工号查询，支持查询及重置；列表工具栏提供“新增员工”和“拉取微信客服”。新增弹窗选择“微信客服ID_微信客服名称”、输入有效员工工号后提交，列表仅展示已关联员工，操作列仅提供“删除”，确认后移除对应关联行；同一微信客服已有员工关联时不能重复新增，删除后可重新选择。拉取使用本地演示客服数据并保留员工关联。默认展示两条已关联样例：小程序商家客服（wk_demo_000001）关联 10001 张敏、订单咨询客服（wk_demo_000002）关联 10002 李佳；删除样例后刷新不会重新出现。演示工号 10001（张敏）、10002（李佳）、10003（王磊）、10004（陈晨），映射在同一浏览器标签页刷新后保留，关闭标签页后清除；未连接微信客服或员工接口。


- 同城 App 顶部功能页签：默认直接进入全部工具，固定提供全部工具页签；打开同城商品、同城商品档案、三方订单、IM消息、同城订单评价后自动新增页签，支持直接切换、关闭和键盘左右切换。重复打开同一菜单复用原页签，切到其他模块后再返回仍保留当前 App 页面。同一浏览器标签页刷新后恢复已打开菜单和当前页；同城商品保留门店、分类、状态、搜索条件、勾选、商品详情及渠道/库存草稿，其他功能恢复主要列表条件及详情位置。关闭页签后刷新不会重新出现。使用 sessionStorage 保存导航状态，上传文件和临时弹层不跨刷新保存，不执行后台业务。

- 页面刷新恢复：在同一浏览器标签页中，刷新后恢复已打开页签及当前激活页面；同城券规则同时恢复新建界面和普通表单输入、单选状态。关闭页签后刷新不会重新打开。使用 sessionStorage 保留本次浏览器标签页会话。

- 同城 App → 三方流量 → 同城订单评价：页面标题为“评价管理”，标题下设同城／小程序页签，默认同城展示现有评价，小程序显示“待设计”；新增移动端评价卡片，顶部仅展示评价时间、门店、筛选；点击筛选后从顶部向下展开选项面板，按参考图提供渠道（不含淘鲜达）、满意程度、是否回复，支持单选、重置和确定查询；点击遮罩收起且不应用未确认修改。筛选按钮后显示当前评价条数，支持商品收展与回复。八条评价以参考截图为基础，渠道名称按美团、淘宝、京东、抖店、自营演示，默认选择全部门店，顶部下滑门店面板支持全部业态、便利店、果多美、果多美抖店切换与关键字搜索；确认后应用，取消不改变选择。果多美门店按参考截图录入，新增业态暂无评价演示数据，回复仅保留当前页面会话；业态、商品明细及补充评论为演示数据；卡片首行展示渠道、门店和时间，订单号在底部左侧，与右侧回复按钮同行，评分按总分、质量、包装单行展示，每项分数保留一位小数且后跟一颗星，5分整星、不满5分半星，顾客评论下方支持图片缩略图及点击放大（复用本地商品示例插图，仅供布局演示），商品默认显示两件并支持展开剩余商品，商品行右侧用单个线框赞或踩图标（点赞橙色、点踩灰色）展示顾客评价，不展示数量，不连接实际业务。

- 同城 → 同城商品管理 → 同城门店商品：按参考截图复刻门店商品筛选、商品类型页签、渠道上下架、批量处理、状态同步与分页交互；渠道售价右侧展示分渠道加价率；接收线下状态同步的上下架、价格、库存均使用下拉框；价格选择启用/停用应用于全渠道，点击“部分启用”可查看并修改各渠道同步设置，保存后自动汇总为启用/部分启用/停用，取消或 Esc 不保存；设置仅保留在当前页面会话，价格和库存同步筛选与列表状态一致。列表使用六条演示商品数据，加价率为示例配置值，不连接实际门店或渠道。
- 同城 App → 三方流量 → 同城商品：按参考截图复刻商品管理页，支持状态/分类筛选、上架、下架、临时下架及门店切换。输入商品名称、编码或条码并点击搜索后进入独立的全宽结果页，保留已提交条件；点击“批量管理”进入同一页面，条件框为空，展示当前门店全部演示商品，可在页内继续输入条件点击搜索。底部固定提供全选、批量上架、批量下架、临时下架，查询后清除旧勾选，操作后清除勾选并提示数量；返回或关闭结果页恢复原分类和状态。点击商品图片、名称或卡片信息可进入商品详情，展示编码、条码、规格、单位，以及自营、京东到家、美团外卖、饿百、抖店的当前价格和独立上下架开关（仅显示商品已关联渠道）；“保存上下架”右侧提供“临时下架”，点击后当前商品所有关联渠道同步下架并保留未提交库存输入；“保存上下架”和“保存库存”分别提交，库存校验非负整数，返回/关闭/取消丢弃未保存修改并保留原列表条件、勾选和滚动位置，已保存库存与渠道状态在当前门店会话内生效。首条薯片渠道价格按截图录入，其他商品渠道价格为原型演示值。总数为截图样例，管理页保留四条水果演示数据，搜索/批量管理增加四条截图商品，共八条；其他分类展示空状态，门店数据按当前页面会话隔离，不连接实际业务。

## 产品原型统一设计规范（强制执行）

本原型目录内后续所有新增、复刻和修改页面，都必须遵循项目 Design System 与 Design Token，不得根据参考截图的物理像素直接放大字号或组件尺寸。

### 规范优先级

1. 项目 Design System 标准文档与 Design Token。
2. 当前原型中已经落地的同类页面和公共组件规格。
3. 参考截图中的结构、字段、顺序、布局关系和业务内容。

当参考截图的字号、颜色、间距或组件尺寸与项目规范不一致时，默认以 Design System 为准；只有用户明确指定覆盖标准时，才使用特殊规格。

### PC 后台基础规格

- 页面标题：`--font-size-page-title`，默认 `18px`。
- 正文及表格数据：`--font-size-body`，默认 `14px`。
- 次级说明：`--font-size-secondary`，默认 `12px`。
- 表头：`--font-size-table-header`，默认 `13px`。
- 按钮文字：`--font-size-button`，默认 `14px`。
- 常规按钮和输入控件高度：默认 `32px`。
- 标准表头高度：默认 `48px`。
- 标准单行表格数据行高度：默认 `48px`。
- 页面间距优先使用 `--spacing-xs`、`--spacing-sm`、`--spacing-md`、`--spacing-lg`、`--spacing-xl`。
- 颜色、圆角、背景和交互状态必须优先使用现有语义 Token，避免新增含义重复的硬编码值。

### 查询列表样式（统一标准）

- 全局 PC 查询列表以“同城商品管理（统一分类）”菜单的查询列表为样式参考。
- 查询条件区与下方列表工具栏、表格之间不增加分隔横线；查询容器不使用边框或投影形成分隔，使用留白区分区域。
- 输入框、下拉框、按钮及表格内部边框沿用现有设计规范。
- 后续新增、复刻及修改查询列表页面时统一遵循，无需用户重复强调。

### 字段提示图标（统一标准）

- 所有字段旁用于鼠标悬停说明的提示小图标，统一使用明亮橙黄色实心圆底、白色 `i`，参考项目提供的“起购数”提示图标。
- 背景色复用 `--color-warning`（`#f79009`），默认尺寸 `14px × 14px`；不得使用蓝色或灰色提示图标。
- 鼠标悬停或键盘聚焦时，以浮层展示说明；移开或失焦时收起，不将说明直接铺在表单中。
- 本规范适用于后续所有新增、复刻及修改的字段提示图标，无需用户再次强调。

### 复刻与实现要求

- 截图用于还原页面结构、字段、文案、列顺序、信息层级和相对布局，不作为字号与控件尺寸的直接标尺。
- 优先复用现有导航、页签、按钮、表格、弹窗、筛选器、分页和反馈样式。
- 新页面必须接入现有菜单、页签和页面切换机制，切换时不得与其他页面重叠。
- 不得增加用户未要求的字段、状态、操作列、统计指标或业务字典。
- 业务规则说明、重要操作提示和注意事项必须使用统一提醒容器，包含提醒图标、浅色语义背景、语义边框和语义文字色；普通提醒优先复用现有浅黄色 Warning 样式，错误或阻断信息才使用 Danger 样式，正文较多时应分条展示。
- 宽表使用横向滚动，不通过压缩字体或异常缩小列宽解决。
- PC 后台与同城 App 应分别沿用各自已有的组件和响应式规则，不混用视觉尺寸。

### 完成前检查

- 检查实际计算字号、按钮高度、表头和数据行高度是否符合 Token。
- 检查表头数量、列定义数量与每行单元格数量一致。
- 检查重复 HTML ID、JavaScript 语法和页面切换状态。
- 有截图参考时，应进行浏览器视觉核对，同时确认未因截图分辨率或设备像素比放大整体 UI。

## 移动端截图自动检查（移动端改动交付前必做）

1. 在本原型目录运行 `node tests/check-mobile.cjs`：检查移动端脚本语法、本地截图库、页面片段同步及截图/导航回归测试。
2. 通过本地 HTTP 预览打开 `tests/mobile-screenshot-check.html?autorun=1`。检查页自动调用实际的 `createTongchengAppScreenshot`，覆盖工具页、商品管理/搜索/批量全选/详情开关/临时下架、商品档案列表/详情、评价、IM列表/会话、三方订单/返图；检查 PNG 类型、尺寸、透明区域和采样颜色，并展示每张实际 PNG。
3. 查看生成图中图片、文字、圆点/勾号及边界是否完整。必须全部通过；新页面或重要子状态同步新增场景。
4. 回到本次修改页，实际点击“复制 App 截图”，确认复制成功或下载降级，按钮最终恢复可点。

真实检查页使用独立会话键，不修改正常原型导航记录。不把普通浏览器截屏或模拟渲染器的测试当作截图功能已经通过。

截图库已固定为 `assets/vendor/html2canvas-1.4.1.min.js`，无需运行时访问 CDN。截图克隆会把自绘 checkbox/radio 转成保留样式和伪元素的 span，并展开圆点的纯位移；真实页面控件保持原样，避免 input 伪元素造成空计算样式 EOF 及圆点错位。
